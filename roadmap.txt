1. Mérföldkő: Az Adatforrások megszelídítése (Extract)

Regisztrálunk az ingyenes API-khoz.

Írunk egy Python scriptet, ami lekéri mondjuk 5 nagy európai repülőtér (pl. London, Frankfurt, Budapest) aktuális érkező/induló járatait, és melléjük húzza az adott városok percre pontos időjárását.

2. Mérföldkő: A Data Lake felépítése (Terraform + Load)

A Terraformmal létrehozunk egy Google Cloud Storage (GCS) "vödröt" (bucket).

Megtanítjuk a Python scriptet, hogy a nyers JSON fájlokat ide töltse fel, ne a gépedre. Ez lesz a "Bronz" rétegünk.

3. Mérföldkő: Az Adattárház és a Csillagséma (dbt Transform)

A GCS-ből átmozgatjuk az adatokat a BigQuery-be.

A dbt-vel megépítjük a gyönyörű relációs adatbázist (Ténytábla a járatokról, Dimenziótábla a repterekről és az időjárásról).

4. Mérföldkő: Robotpilóta (Orchestráció)

Az egészet feltesszük a felhőbe, hogy óránként automatikusan lefusson.




1. Extract (A Kinyerés - Több adatforrásból)
Ahelyett, hogy egy API-t használnál, most kettőt fogsz összekötni. Ez egy nagyon gyakori (és nehéz) feladat a piacon.

Forrás 1: OpenSky Network API vagy AviationStack API (Élő járatinformációk, indulások, érkezések, késések).

Forrás 2: OpenWeather API (Az indulási és érkezési repülőterek aktuális időjárása).

Új skill: A Python kódodnak le kell kezelnie az API limitációkat (Rate Limiting), és a bonyolult, több szinten ágyazott JSON fájlokat.

2. Load (A Betöltés - Bevezetjük a Data Lake-et!)
A LoL projektben a Python egyből a BigQuery-be írt. A nagy cégeknél ez sosem így működik.

A Bronz Réteg (Data Lake): A Python kódod a nyers, érintetlen JSON fájlokat először felölti a Google Cloud Storage (GCS)-be (ez egy virtuális merevlemez a felhőben).

Az Ezüst Réteg: Egy másik lépés (pl. a BigQuery külső tábla funkciója) beolvassa a GCS-ből a nyers adatokat a BigQuery-be.

Új skill: Ez biztosítja, hogy ha elrontod a transzformációt, a nyers adat mindig megvan a Data Lake-ben (GCS), és bármikor újra tudod tölteni.

3. Transform (A dbt Csillagséma - Az Arany Réteg)
Itt jön a feketeöves adatmodellezés. A nyers adatokból a dbt segítségével egy tökéletes Csillagsémát (Star Schema) építesz:

fct_flights (Ténytábla): Ez tartalmazza magát az eseményt. flight_id, departure_airport_id, arrival_airport_id, weather_id, delay_minutes.

dim_airports (Dimenzió): Repülőterek adatai (IATA kód, Város, Ország, Földrajzi koordináták).

dim_weather (Dimenzió): Hőmérséklet, Szélsebesség, Vihar státusz.

dim_airlines (Dimenzió): Légitársaság neve, alapítás éve.

4. Tesztelés (Data Quality a köbön)
Ebben a projektben rengeteg dolgot lehet tesztelni dbt-vel:

Logikai tesztek: Az arrival_time (érkezés) szigorúan nagyobb kell, hogy legyen, mint a departure_time (indulás).

Integritási tesztek: A ténytáblában szereplő airport_id-nek kötelezően léteznie kell a dim_airports táblában (ezt hívják referenciális integritásnak).

Érték tesztek: A repülőgép magassága nem lehet negatív szám.

Miért ez a tökéletes projekt számodra?
Időzónák kezelése (Timezones): Az adatmérnökök rémálma, te viszont megtanulod kezelni (pl. Tokióból induló gép Londonba érkezik, hogyan számolod ki a pontos repülési időt UTC-ben?).

Data Lake bevezetése: A Terraformmal most nemcsak BigQuery-t, hanem Google Cloud Storage bucketet is fogsz kreálni.

Multi-source JOIN-ok: Össze kell fésülnöd a repülős adatbázist az időjárásival, aminek a kulcsa (JOIN key) a város és a pontos óra lesz.
